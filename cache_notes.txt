To monitor whether or not a GET request returns a cached response or not, the Products API controller result DTO has a property of "FetchedTime" that is 
populated with the current server time by the controller when the response is generated by the controller action.  If the response is served from cache, 
the controller action will not run, and the property will not be updated and this time will be earlier than the current or page render time.  Doing it this way avoids 
setting a property on the actual entity as it is outside of the scope of the domain, and also avoids having to modify services and objects used by the controller.

Note when viewing storefront the list of products is maintained when view the cart or product details, so the page rendered time is displayed instead of current time.

Added both OutputCache and ResponseCache with OutputCache currently commented out to Products Read Side API.  

Blazor Admin Client and Blazor Consumer Client have elements on the Storefront.razor Products List and Storefron Detail pages to see FetchTime of the product or 
	product collection as well as either page render time or current time.

If the request to the API has an Auth header it will prevent caching (both Response and Output Caching) 
	Consumer Blazor Client: If user goes to storefront anonymously, caching is operational, but once user logs in, caching will no longer be available.
	Admin Blazor Client: User must be logged in to access the Admin API, so caching is not operational.
